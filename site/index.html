Under the hood

Give your agent a way to measure.

The skill gives your coding agent a repeatable profiling workflow. It explains how to run the local CLI, interpret the measurements, and check a code change against a saved baseline.

Profile your running app.

The CLI opens your WebGPU or WebGL app in Chrome, injects API instrumentation, and samples frame pacing, draw calls, and declared buffer and texture allocations. Optional Chrome traces add context about browser activity when a capture needs closer investigation.

Give the agent evidence to act on.

A compact diagnostic summary keeps the agent’s context small; the full capture is saved locally as JSON. The skill guides the agent to investigate the measurements, change one suspected bottleneck, and preserve the scene’s visual behavior before capturing again.

Check whether the change helped.

Compare baseline and candidate reports with identical sampling settings. The tool reports metric changes, confidence intervals where repeated data supports them, and regressions against configured thresholds. Invalid captures, incompatible settings, and inconclusive results are flagged explicitly.

Keep the loop fast and inspectable.

Reuse Chrome across captures to reduce startup overhead. Use longer sampling or interleaved A/B runs for stronger evidence. Saved JSON, optional HTML reports, and performance budgets make the results useful for code review and automated regression checks.

Frame pacing measures browser cadence; GPU duration requires timing hooks. Allocation totals estimate declared storage, not physical VRAM residency. Read the measurement reference ↗
